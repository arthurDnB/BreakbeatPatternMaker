# Modular synth realism upgrade — implementation plan

**Status:** design for review; no DSP or factory patch changes are made by this document.  
**Scope:** the patchable browser synth, its project format, audition, playback, and WAV export.  
**Goal:** more expressive, recognizable instrument emulations. “Realistic” is an audition result, not a property that can be guaranteed by a recipe or a unit test.

## 1. Evidence and present implementation

The current [`src/audio/modular-synth.ts`](src/audio/modular-synth.ts) offers oscillator (including optional warmth), sample, mixer, multimode filter, amplifier, ADSR, LFO, velocity, attenuverter, chorus, delay, reverb, distortion, noise, and output. The existing oscillator **already accepts pitch CV** (`input * 12` semitones), so the missing feature is a controlled *audio-rate* modulation path and a more articulate multistage envelope, not basic pitch routing. White/pink noise is already deterministic. Existing `starterPatch` presets for nylon guitar, Rhodes, strings, flute, brass, slap bass, and vibraphone are subtractive approximations; keep them unchanged as legacy factory recipes until a new one passes listening review.

The patch contract in [`src/core/model.ts`](src/core/model.ts) is `SynthPatch {version:1,nodes,cables}` with numeric/string module parameters and typed audio/control ports. `validateSynthPatch` permits 3–32 nodes, at most 64 cables, matching port types, one output, an audio-source-to-output path, and **no cable feedback cycles**. Rendering is note-local, sample-accurate at 8–192 kHz, and shared by audition and production. Per-note module state includes an LCG for noise; the final output uses `tanh`. [`src/ui/synth-patch-editor.ts`](src/ui/synth-patch-editor.ts) builds its palette from `SYNTH_MODULES`, so new definitions automatically appear; factory names still require an explicit dropdown entry. [`src/audio/project.ts`](src/audio/project.ts) stores modular projects as project v9; older unpatched synth tracks use their separate renderer and must retain identical PCM. [`src/audio/performance.ts`](src/audio/performance.ts) caches voices and imposes a 128 MB synth-cache cap.

| Desired behavior | Present gap | Direction |
|---|---|---|
| Dynamic tine and reed overtones | Oscillator has no audio-rate modulation input; `pitch` is control and has semitone-scale gain | Add a new phase-modulation operator with audio modulation, a ratio, and its own index CV; do not alter old oscillator math |
| Tuned plucked-string sustain | Delay has 20 ms minimum and is a generic effect | Add a pitch-tracking, fractional-delay string resonator with *internal* damped feedback |
| Moving body/reed peaks | One bandpass filter per node; no coordinated multi-peak formant | Add a three-band formant bank with bounded peaks and key tracking |
| Metallic sidebands | No audio-by-audio multiplication | Add a ring modulator; use a modal bank when struck-metal pitches need individually decaying inharmonic modes |
| Instrument attack articulation | ADSR can route to pitch but has only four fixed phases | Add a bounded multistage CV envelope and signed pitch-depth control; retain ADSR for old patches |
| Acoustic plausibility | Existing presets mostly use static waveforms and global effects | Add velocity-dependent attack, note-range scaling, separate excitation/body paths, and listening gates |

These choices follow the original [Karplus–Strong paper](https://www.moforte.com/wp-content/uploads/2020/05/Karplus-Strong-CMJ-1983.pdf), [SuperCollider's Pluck implementation](https://doc.sccode.org/Classes/Pluck.html), [Csound's waveguide models](https://csound.com/docs/manual/SiggenWavguide.html), [Csound's FM opcode](https://csound.com/docs/manual/foscili.html), and [SuperCollider's modal resonator documentation](https://doc.sccode.org/Classes/Klank.html). Gordon Reid's [brass](https://www.soundonsound.com/techniques/synthesizing-brass-instruments), [flute](https://www.soundonsound.com/techniques/practical-flute-synthesis), [guitar](https://www.soundonsound.com/techniques/final-attempt-synthesize-guitars), and [bell](https://www.soundonsound.com/techniques/synthesizing-bells) studies emphasize evolving envelopes, body response, and limits of simple subtractive patches. [Rhodes' V8 manual](https://download.rhodesmusic.com/assets/RHODES-V8PRO/Rhodes%20V8%20Manual%20v3.pdf) identifies a hammer-struck tine and per-note pickup; [Yamaha's DX7 manual](https://usa.yamaha.com/files/download/other_assets/3/320813/DX7SE.pdf) documents operator ratios and algorithms. Reddit sound-design posts can suggest audition ideas but are not used as engineering evidence.

## 2. DSP and data contract

**Compatibility rule:** retain `SynthPatch.version === 1`, the existing project-v9 envelope, all legacy module types and parameter defaults, and every old render branch. New node types are opt-in. A stored v9 patch can be validated and rendered without migration or changed PCM. If implementation reveals any unavoidable legacy math change, introduce a patch engine revision and dispatch old patches to the old renderer instead of silently changing them. Snapshot old PCM at 44.1/48 kHz before work starts.

| New node / port | Parameters (allowed range; initial) | Inputs → output | DSP/guard |
|---|---|---|---|
| `fm-operator` | `ratio` 0.25–24; 1, `fineCents` −100–100; 0, `mode` phase/linear/exponential; phase, `index` 0–12 radians; 0, `deviationHz` 0–8000; 0, `expSemitones` 0–48; 0, `level` 0–1; .5 | `mod:audio`, `indexCv:control`, `pitch:control`, `gain:control` → `out:audio` | Let `fbase=f0·ratio·2^((fineCents/100+12·pitch)/12)` and `m=clamp(mod,−1,1)`. Phase mode: `y=sin(φ+clamp(index+12·indexCv,0,12)·m)` with `φ+=2πfbase/fs`. Linear mode: `φ+=2π·clamp(fbase+deviationHz·m,0,.44fs)/fs`; exponential mode: `φ+=2π·clamp(fbase·2^(expSemitones·m/12),0,.44fs)/fs`. In linear/exp mode, `indexCv` scales the deviation/exp depth by `clamp(1+indexCv,0,2)`. Clamp phase advance and output at finite bounds. The **phase** setting is DX-style PM with FM-like sidebands; the two frequency settings are true sample-rate FM variants. |
| `string-resonator` | `decaySeconds` .05–12; 2, `damping` 0–1; .35, `pluckPosition` .05–.95; .25, `bodyMix` 0–1; .25, `level` 0–1; .5 | `excite:audio`, `pitch:control` → `out:audio` | Pitch-tracking fractional delay `D ≈ fs/f − filterDelay`; bounded damped feedback `0≤g<1`, one-pole low-pass in loop, seeded excitation/noise burst. Correct tuning after the filter's phase delay is measured. Feedback lives *inside this node*; no graph cycle is permitted. |
| `formant-bank` | `f1` 120–4000; 650 Hz, `f2` 300–6500; 1400, `f3` 500–9000; 2600, `q1/q2/q3` .4–20; 3/4/5, `a1/a2/a3` 0–1; .6/.35/.2, `wet` 0–1; 1 | `in:audio`, `shift:control` → `out:audio` | Three stable parallel bandpass/SVF sections; `fi' = clamp(fi·2^(shift·2), 30, .45fs)`; normalize summed peak energy and remove DC. Fixed peaks alone cannot reproduce every acoustic articulation. |
| `ring-mod` | `amount` 0–1; 1, `dry` 0–1; 0 | `a:audio`, `b:audio`, `amountCv:control` → `out:audio` | `y = dry·a + amount·clamp(amountCv,0,1)·(a·b)`; if CV disconnected treat as 1. Bound each input and output. |
| `multi-envelope` | `attack` .001–2; .01 s, `hold` 0–2; 0, `fall` .001–3; .12 s, `breakLevel` 0–1; .5, `slope` −1–1; 0, `sustain` 0–1; .5, `release` .01–8; .3 s, `delay` 0–2; 0 s | `velocity:control` → `out:control` | Piecewise continuous delay/attack/hold/fall/sustain/release with finite corners. Output 0–1; a separate attenuverter makes bipolar pitch/filter depth. Note-off release starts from instantaneous held value. |
| `modal-bank` (second wave, only if required by mallet audition) | `r1/r2/r3` .5–16; 1/3.9/9.2, `t1/t2/t3` .01–10; 2/.5/.15 s, `a1/a2/a3` 0–1; .8/.3/.1 | `excite:audio`, `pitch:control` → `out:audio` | Three independently damped second-order resonances at `r_i·f0`; disable a mode when `r_i·f0 > .45fs`. Normalize across rate and mode count. |

**Existing nodes used unchanged:** oscillator, noise, mixer, filter, amplifier, ADSR, LFO, velocity, attenuverter, chorus, delay, reverb, distortion, output. The new FM node provides the audio-rate input without weakening the validator's port types. New recipe graphs use only audio→audio and control→control cables. A depth on any edge is still in `[-1,1]`; large pitch excursions come from the destination's documented scaling or a bounded CV processor, not an out-of-range cable. Extend `validateSynthPatch` source recognition to `fm-operator` where an unmodulated carrier can self-source; a string/modal resonator still needs an excitation source.

**Numerics and memory:** calculate all frequency-dependent coefficients from `rate`, clamp at `.44–.45·rate`, enforce finite controls and state after every potentially unstable operation, and allocate delay/modal state once per note. A 20 Hz resonator at 192 kHz needs roughly 9,600 samples/channel; cap per-voice state and total cache. Do not use `Math.random()`; derive any extra seeds from stable patch/node/note/channel values using the existing integer LCG. If two same-pitch notes should differ, thread in a stable hit/event key explicitly and include it in the synth cache key. Up to that point, identical input notes remain bitwise identical. Keep final output limiter behavior and match peak/RMS levels before judging timbre.

**High-frequency caution:** simple FM and ring modulation alias readily. Begin with bounded index/ratios and reject partials above Nyquist; if listening tests reveal foldback, add 2× or 4× oversampling with proper anti-alias downsampling *only to new nodes*. A claimed universal “1:14 Rhodes ratio” is not justified by the sources: treat 1:7 and 1:14 as optional bright-tine audition candidates, especially at high C5 where upper sidebands disappear or alias. The correct ratio is chosen by matched reference listening, not by one hard-coded legend.

Build a static recipe validator that expands defaults, rejects any nonexistent port or unintended duplicate path, and checks output connectivity. All prototype figures must be adjusted against licensed recordings before promotion from “experimental” to “factory”.

## 4. Editor and product integration

- Add palette groups **Sources**, **Modulation**, **Resonators & Filters**, **Effects**, **Routing** while retaining keyboard-operable port buttons, labels, validation errors, and existing saved patches. `fm-operator` audio modulation ports and `multi-envelope` CV ports need distinct colors and units; show Hz, cents, radians, and seconds, not anonymous 0–1 knobs.
- Organize factory choices into **Acoustic-inspired**, **Electromechanical**, **Winds & Brass**, **Mallets & Metals**, and **Classic Synths**. Preserve current preset IDs and labels for old user projects; give reviewed versions new IDs such as `rhodes-model-v2`. Select a factory patch as an editable draft until **Use this patch**. Add brief recipe disclosures (“synthesized approximation”; “sample recommended for closest realism”).
- Expose velocity sensitivity, note range, and expression with meaningful labels. Audition at C1–C5, soft/medium/hard velocities, and short/long gates, not just a single C4 note. The patch editor's current preview path can accept velocity as an optional extension; Preview and WAV must use the same renderer and asset selection.
- Treat instruments needing nonlinear excitation or physical coupling (solo violin bow friction, flute jet, sax reed, Wurlitzer reed, sitar sympathetic strings) as **future dedicated models or sample hybrids**. Chorus/detune/formant alone should not be advertised as a high-fidelity physical model.

## 5. Build sequence and quality gates

1. **Baseline and listening pack.** Freeze reference PCM hashes and render cost for all current factory patches, old v9 project fixtures, C1–C5, 44.1/48 kHz, and soft/hard velocities. Secure redistributable or local-only instrument reference clips at matched pitch/velocity; keep copyrighted reference audio out of the repository unless licensed. Capture attack, steady-state, release, spectrum, RMS, true peak, and subjective listening notes.
2. **Core contracts.** Add optional new module types/typed ports in `model.ts` and `modular-synth.ts`; write validator tests for bounds, missing ports, source reachability, cable depth, cycle rejection, and malformed v9 project input. Preserve existing node dispatch exactly.
3. **First DSP tranche.** Implement phase-modulation operator, multistage envelope, and pitch/filter CV mapping. Use a Rhodes and a metallic test patch. Measure aliasing at C5/192 kHz and low-rate stability at 8 kHz; add oversampling only where needed.
4. **Second DSP tranche.** Implement string resonator with fractional delay, damping, and calibrated pitch, then formant bank and ring modulator. Validate identical pitch across sample rates and bounded decay for notes C1–C5. Add the modal bank only after A/B confirms a simpler FM/ring patch is insufficient for mallets.
5. **Patch curation.** Ship one patch family at a time: Rhodes/Wurly/Clav → nylon/slap → winds/brass → mallets → bowed ensemble. Use the prototype matrix as search bounds. Build an audition page with randomized blind A/B against the current patch at matched LUFS/peak, and record per-register feedback. Promote only patches that consistently win; a sampled or hybrid fallback is acceptable.
6. **UI and save integration.** Add palette grouping, parameter units, velocity/gate audition, and stable factory IDs. Verify save/reopen, old project migration-free load, patch recall, Undo, arrangement, Preview/WAV PCM parity, and exported audio. Use a retained reference render for regression.
7. **Performance gate.** Measure 4/8/16-note chords and a dense arrangement at 44.1/48/96/192 kHz on the user's target machine; track render time, allocations/voice, peak cache bytes, and UI responsiveness. Set a polyphony or quality fallback only from measured data. Reject patches that exceed existing 128 MB cache or produce non-finite output.

Automated tests belong in [`tests/modular-synth.test.mjs`](tests/modular-synth.test.mjs) and [`scripts/modular-synth-browser-smoke.mjs`](scripts/modular-synth-browser-smoke.mjs). Add deterministic PCM assertions, finite/peak and non-silence checks, pitch error in cents, decay envelope and sample-rate invariance, no cable loops, preset expansion/validation, and old-project PCM hashes. Browser checks cover add/patch/edit/preview, keyboard access, save/reopen and export. Run `npm.cmd test` and `npm.cmd run test:site` for each implementation tranche and follow `AGENTS.md` for log, commit, and push. Passing tests establishes function and compatibility; musical plausibility requires listening review.

**Review decision before implementation:** approve the opt-in module contract and which three instrument families to audition first. The proposed order prioritizes Rhodes, nylon guitar, and flute because they exercise FM, string resonation, and wind articulation separately; it does not imply the other nine recipes are production-ready.
